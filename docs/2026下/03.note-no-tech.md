### 制品类型（重点解释）

`OCI-Image-v1`

#### 1) OCI 是什么
**OCI = Open Container Initiative（开放容器规范）**
是 Docker、containerd、K8s 共同遵守的国际容器标准，由 Linux 基金会维护。

#### 2) OCI-Image-v1 含义
- `OCI-Image`：代表这是符合 OCI 标准的容器镜像，不是 Docker 私有的老式格式；
- `v1`：OCI 镜像规范第 1 版本。

#### 通俗理解
1. 早期只有 Docker 自己的镜像格式，兼容性差；
2. 后来行业统一制定 OCI 标准，现在所有云厂商（腾讯 TCR、阿里云 ACR、Harbor、Docker Hub）存储的镜像默认都是 OCI 格式；
3. `OCI-Image-v1` = 标准通用容器镜像，Docker、K8s、nerdctl、containerd 全都能完美解析运行，没有任何兼容性问题。

#### 补充两种常见制品类型对照
- `OCI-Image-v1`：普通容器镜像（你当前前端 Nginx 镜像）
- `OCI-Index`：多架构镜像（同时包含 amd64+arm64，一个 Tag 自动适配不同 CPU）

### `docker compose up` 同时存在 `build` 和 `image` 两个字段时的规则

1. 优先执行本地构建镜像
2. 构建完成后，会给新构建出来的本地镜像打上 `image` 定义的标签
3. 最后再用这个标签启动容器

举个直观例子
```yaml
services:
  backend:
    image: ccr.ccs.tencentyun.com/xxx/backend:1.0.0
    build: ./backend
```

执行 `docker compose up -d` 完整流程：
1. 进入 `./backend` 目录，用 Dockerfile 本地 build 打包
2. 自动给刚打包好的镜像打上 tag：`ccr.ccs.tencentyun.com/xxx/backend:1.0.0`
3. 基于本地这个新镜像启动容器

### 关键坑点（对你现在场景非常重要）
1. 它不会去远程仓库 pull 镜像
哪怕远程 TCR 仓库已经存在 `1.0.0` 版本，compose 也会无视远程，自己在服务器本地重新构建一版，覆盖本地同名镜像标签。
2. 版本完全失控
服务器本地构建的镜像 ≠ 你本地推送到 TCR 的镜像，代码、产物不一致，极易出现线上 BUG。

### 两条命令行为差异
1. `docker compose up -d`
同时有 build + image → 本地构建，不走远程拉取

2. `docker compose pull backend`
只执行拉取操作时，只会读取 image 地址去拉远程镜像，不会触发 build 构建

### 最终给你的最佳实践
#### 1) 生产部部署文件（服务器用）
彻底删掉 `build:` 整行，只保留 `image`，保证永远远程 TCR 已发布镜像
```yaml
backend:
  image: ${TCR_REGISTRY}/${TCR_NAMESPACE}/github-monitor-backend:${BACKEND_TAG}
  # build: ./backend 删掉
```

#### 2) 本地开发调试文件（可以分开）
新建 `docker-compose.dev.yml`，本地开发用，只在自己电脑运行：
```yaml
# docker-compose.dev.yml 本地调试专用
backend:
  build: ./backend
  # image 可以注释掉
```

启动命令：
```bash
docker compose -f docker-compose.dev.yml up --build
```

一句话总结：
- 线上部署只留 image，删掉 build；本地调试单独配置带 build 的 compose 文件。

## 怎么看docker是否已经登录

`2026-09-02`

方式：查看凭据配置文件。docker 登录信息保存在配置文件，Linux/macOS：

```
cat ~/.docker/config.json
```

- 文件内有 `auth` 字段，说明已经登录过对应仓库；
- 如果只有 `credsStore`（凭据管理器），代表密码交给系统保管，**不能直接看到明文 token，但说明执行过 login**。


## Bash 必知

`2026-09-02`

### 看多少核

> **nproc**
> 全称：**number of processors**
> 作用：输出当前系统可用的**逻辑 CPU 核心数**（云主机里直接对应你买的 2 核配额）

```
nproc
# 正常你这台机器会直接输出 2
```

### 查 IP

#### 内网 IP（云服务器内网地址，主机内部网卡地址）

```
# 最简简写（推荐，主流系统都自带）
ip a

# 或者直接干净输出所有内网ip
hostname -I
```

>
> 云厂商控制台显示的**内网 IP**，就和这里的 `inet` 后面地址对上

#### ✅ 2. 公网 IP（对外的 IP，别人访问你服务器用的，重点！）

需要服务器能联网：

```
curl ifconfig.me
# 备选（ifconfig.me访问不通时用）
curl shturl.cc/yb
```

>
> 这个结果就是云厂商分配给你这台机器的公网 IP，和控制台里的公网 IP 核对

### pm2 startup 和 pm2 save

```
# 第一步：先把你的项目 pm2 start 启动好
pm2 start app.js --name api

# 第二步：pm2 startup（生成开机服务，会输出sudo命令，复制执行）
pm2 startup
# 复制输出的sudo xxx那一条执行！

# 第三步：保存当前运行的项目列表
pm2 save
```

>
> 后续如果你新增 / 删除 / 重启了项目，**一定要重新执行 pm2 save**，不然重启服务器不会更新

## 1. 位置编码 (Positional Encoding)

论文 3.5 节

```python
# Transformer 没有 RNN/CNN，本身对序列顺序无感知，
# 因此把「位置」信息以正弦/余弦函数的形式直接加到输入词向量上。
class PositionalEncoding(nn.Module):
    def __init__(self, d_model: int, max_len: int = 5000, dropout: float = 0.1):
        super().__init__()
        self.dropout = nn.Dropout(dropout)

        # pe: [max_len, d_model]，第 pos 行 = 位置 pos 的编码向量
        pe = torch.zeros(max_len, d_model)
        position = torch.arange(0, max_len).unsqueeze(1).float()   # [max_len, 1]
        # 论文公式：div_term = 1 / 10000^(2i / d_model)
        div_term = torch.exp(
            torch.arange(0, d_model, 2).float() * (-math.log(10000.0) / d_model)
        )
        pe[:, 0::2] = torch.sin(position * div_term)   # 偶数维用 sin
        pe[:, 1::2] = torch.cos(position * div_term)   # 奇数维用 cos
        pe = pe.unsqueeze(0)                            # [1, max_len, d_model]
        # register_buffer：不参与梯度，但会随模型一起 save/load、move 到 GPU
        self.register_buffer("pe", pe)

    def forward(self, x):
        # x: [batch, seq_len, d_model]
        x = x + self.pe[:, : x.size(1)]
        return self.dropout(x)
```

### 1.1. 什么是 pe

`pe` 是 **Positional Encoding（位置编码）** 的缩写，是 Transformer 里给模型"告诉它每个词在第几位"的机制。

### 1.2. 为什么需要它

Transformer 没有 RNN/CNN，self-attention 是"并行看所有位置"的——它本身**对词的先后顺序完全无感知**。

所以需要一个东西，把"这是第 1 个词、第 2 个词…"的信息塞进去，否则"我爱你"和"你爱我"对模型来说就没区别了。

### 1.3. `pe` 的形状和含义

```python
# pe: [max_len, d_model]，第 pos 行 = 位置 pos 的编码向量
pe = torch.zeros(max_len, d_model)
```

- `max_len`：最大序列长度（默认 5000）
- `d_model`：词向量维度（比如 128）
- `pe[pos]`：位置 `pos` 对应的那个编码向量

| 名称 | 是什么 | 单位 |
|---|---|---|
| `max_len` | 一句话里**有多少个词**（token 数） | 词的个数 |
| `d_model` | 每个词用**多少维的向量**表示 | 向量的维度 |

假设这句话："I love you very much"（5 个词）

```
I    love   you   very   much        ← 5 个词
[. ] [.  ]  [.  ] [.   ] [.   ]
每个词用一个 d_model 维的向量表示（比如 d_model=128，就是每个词是 128 个数字的数组）
```

- `max_len` = 这句话的词数上限（这句话是 5，但 max_len 通常是"最长允许多少词"，比如 5000）
- `d_model` = 每个词向量的维度（128 就是每个词用 128 个数字表示）

### 1.4. 为什么用 sin 和 cos

这是论文 3.5 节的原版公式：

$$PE(pos, 2i) = \sin\left(\frac{pos}{10000^{2i/d_{model}}}\right)$$

$$PE(pos, 2i+1) = \cos\left(\frac{pos}{10000^{2i/d_{model}}}\right)$$

对应代码：

```python
pe[:, 0::2] = torch.sin(position * div_term)   # 偶数维用 sin
pe[:, 1::2] = torch.cos(position * div_term)   # 奇数维用 cos
```

- `0::2` 是 Python 切片：从 0 开始、步长 2 → **第 0、2、4、6… 维（偶数维）**
- `1::2` 是第 1、3、5、7… 维（**奇数维**）
- 偶数维填 sin，奇数维填 cos，交替填充

#### 1.4.1. 为什么这个设计好

用 sin/cos 有个漂亮的性质：**任意两个位置之间的编码可以线性表示**。即 `PE(pos + k)` 可以通过 `PE(pos)` 的某个线性变换得到。这让模型能自然地学到"相对位置"关系（"这个词前面第 3 个词是谁"），而不是只能记住绝对位置。

而且它是**固定的、不需要训练的**，生成一次就能给所有长度的序列复用（比可学习的位置向量更泛化）。

这两个性质确实是 sin/cos 位置编码最精妙的地方，也是它比"可学习位置向量"更优雅的原因。

#### 1.4.2. 性质一：相对位置可以线性表示

##### 1.4.2.1. 先建立直觉：把编码看成"表盘上的指针"

只看位置编码的一对维度（第 `2i` 维是 sin，第 `2i+1` 维是 cos），对某个固定频率 `ω`，位置 `pos` 的编码是：

```
PE(pos) = ( sin(pos·ω),  cos(pos·ω) )
```

这其实就是**单位圆上的一个点**，或者说一根"指针"：

- 位置 0 → 指针指向 (0, 1)（正上方）
- 位置 1 → 指针转了一格
- 位置 pos → 指针转了 pos 格

`pos` 越大，指针转过的角度越大。**"位置"就变成了"角度"**。

##### 1.4.2.2. 关键数学事实：平移位置 = 旋转指针

从位置 `pos` 走到位置 `pos+k`，指针就是**多转了 k 格**。而"多转 k 格"在二维平面上就是一个**旋转矩阵**：

$$PE(pos+k) = \underbrace{\begin{bmatrix} \cos(k\omega) & \sin(k\omega) \\ -\sin(k\omega) & \cos(k\omega) \end{bmatrix}}_{只含 k，不含 pos} \cdot PE(pos)$$

这个矩阵**只跟相对距离 `k` 有关，跟绝对位置 `pos` 完全无关**。

（这就是三角函数的和角公式：`sin(a+b) = sin a·cos b + cos a·sin b`，展开一下就是上面的矩阵形式。）

##### 1.4.2.3. 这句话到底在说什么

**"PE(pos+k) 可以通过 PE(pos) 的某个线性变换得到"** 的精确含义是：

> 不管你在第 3 个位置还是第 300 个位置，只要"往后走 k 步"，编码的变化方式是完全一样的——就是乘同一个旋转矩阵。

##### 1.4.2.4. 为什么这让模型能学到"相对位置"

模型在训练时会看到大量"词 A 在第 5 位、词 B 在第 8 位"这样的模式。因为编码是 sin/cos：

- 模型**不需要**记住"第 8 位长什么样"（绝对位置）
- 模型**只需要**学会"相隔 3 个位置，编码之间就差一个固定的旋转矩阵"（相对关系）

一旦模型掌握了"距离 = k 的编码变换"，那么：

- "第 2 个词和第 5 个词相隔 3"
- "第 100 个词和第 103 个词相隔 3"

这两个场景对模型来说是**同一件事**（都是"相隔 3"），因为编码的变换矩阵一模一样。这就是"相对位置关系"能力——模型学到的是一种**可迁移的规则**，而不是死记每个绝对位置。

#### 1.4.3. 性质二：固定、不需训练、可泛化任意长度

##### 1.4.3.1. 先对比"可学习位置向量"

可学习位置向量是另一种做法：`pos` 位置的编码是一个**模型参数**（随机初始化，训练中更新）。它有个致命问题：

- 训练时句子最长 50 词 → 只学习了位置 0~49 的编码
- 测试时来了个 100 词的句子 → 位置 50~99 **从没见过**，模型没有这些位置的编码参数，要么报错，要么瞎猜

它被"训练时见过的最长句子"卡死了。

##### 1.4.3.2. sin/cos 为什么没这个问题

sin/cos 编码**不是一个表，而是一个公式**：

$$PE(pos, i) = \sin(pos \cdot \omega_i)$$

给定任意 `pos`，代入公式就能算出编码。代码里那个 `pe = torch.zeros(max_len, d_model)` 的 `max_len=5000` **只是"预先算好了前 5000 个位置存起来"，不是能力的上限**。

- 训练时见过 50 词的句子
- 测试时 100 词的句子 → 位置 50~99 照样用公式算出来（公式对任何 `pos` 都成立，是连续函数）

所以它天然支持"训练短、推理长"的泛化场景。

##### 1.4.3.3. "固定"意味着什么

`pe` 里没有任何需要训练的权重，`register_buffer` 也标明它**不参与梯度更新**：

```46:46:transformer_pytorch.py
        self.register_buffer("pe", pe)
```

它是"白送的"位置信息，不占模型的学习负担，模型把参数全部省下来学"词义"和"注意力"，位置信息由公式免费提供。

#### 1.4.4. 总结对照

| | sin/cos 位置编码 | 可学习位置向量 |
|---|---|---|
| 相对位置 | ✅ 平移 = 旋转矩阵，可迁移 | ❌ 每个位置独立参数，无相对结构 |
| 是否训练 | ❌ 固定，不占参数 | ✅ 需要训练 |
| 泛化到更长句子 | ✅ 公式连续，任意长度 | ❌ 被训练最大长度卡死 |
| 模型要学什么 | 只需学"距离 k 的旋转" | 每个绝对位置各学各的 |

#### 1.4.5. 一个补充

这个"旋转矩阵"视角后来直接催生了一个更强的方案——**RoPE（旋转位置编码）**，现在 ChatGPT、Llama 等大模型都在用。它的核心思想就是：把"位置 = 旋转角度"这件事从"加到向量上"改成"直接旋转词向量本身"。现在这套 sin/cos 直觉，正是读懂 RoPE 的基础。

一句话：**sin/cos 让"位置"从"一张要背的表"变成了"一个可旋转的角度"，所以位置关系能迁移、能外推、还不用训练。**

### 1.5. 这个是 transformer 这个论文里发明的吗

**"用 sin/cos 编码位置"这个具体做法是 Transformer 论文（2017）提出并普及的，但"位置编码"这个思想有更早的前身**。

#### 1.5.1. Transformer 论文确实"发明"了 sin/cos 这个具体公式

论文《Attention Is All You Need》第 3.5 节专门写了它，公式就是你现在代码里的：

$$PE(pos, 2i) = \sin(pos/10000^{2i/d})$$

这是论文的贡献之一。而且论文里还**明确对比了可学习版本**（learned positional embeddings），在 Table 3 里报告说两者效果差不多，但选了 sinusoidal 版本，理由是能外推。

#### 1.5.2. 但"位置编码"这个思想不是 Transformer 首创

关键前身是 **ConvS2S**（Convolutional Sequence to Sequence Learning, Gehring et al., ICML 2017），它**和 Transformer 同年、早了几个月**，首次在 seq2seq 里显式用了 **position embedding（可学习的）**——把位置信息作为一个可训练的参数加到输入上。

再往前，更早的 seq2seq 机器翻译（Bahdanau 2014、Luong 2015 这些带 attention 的）都用 **RNN**，而 RNN 靠"一步步顺序读"天然就带位置信息，所以**根本不需要**额外编码位置。

所以逻辑链条是：

```
RNN 时代       → 架构自带顺序，不需要位置编码
ConvS2S (2017) → 卷积也部分有顺序，但显式加了"可学习位置向量"
Transformer    → 纯 attention 完全无顺序，提出"sin/cos 正弦位置编码"
```

#### 1.5.3. 那个"漂亮性质"其实不是论文严格证明的

有意思的是，"相对位置可以线性表示、旋转矩阵"这个**严格的数学解读，并不是 Transformer 论文自己证明的**。

论文原文只是**猜测**（原文用词是 "we hypothesized"）：

> We chose this function because we hypothesized it would allow the model to easily learn to attend by relative positions, since for any fixed offset k, PE_{pos+k} can be represented as a linear function of PE_{pos}.

翻译：我们选这个函数是因为**我们假设**它能……（一句话带过，没有展开证明）。

真正把"sin/cos = 旋转矩阵"这件事**严格形式化并加以利用**的，是后来的工作——尤其是 **RoPE（旋转位置编码，2021）** 和同期一批位置编码分析论文。RoPE 把这个想法推到了极致（不再"加"位置编码，而是直接"旋转"词向量），现在 ChatGPT、Llama 都在用。

#### 1.5.4. 更古老的思想源头（信号处理）

如果追根溯源，"用正弦函数表示位置/时间"其实来自**傅里叶分析 / 信号处理**——用不同频率的 sin/cos 波去表示信号里的"时间结构"，这是几百年的数学思想。Transformer 论文把它搬到了"token 位置"上。

#### 1.5.5. 一句话总结

| 概念 | 谁提出的 |
|---|---|
| 位置编码（可学习） | ConvS2S (2017)，比 Transformer 早几个月 |
| **sin/cos 正弦位置编码** | **Transformer 论文 (2017)** ✅ 论文原创 |
| "相对位置 = 线性变换"的严格形式化 | RoPE 等后续工作 (2021) |
| sin/cos 表示时间 | 傅里叶/信号处理（更古老） |

所以准确说法是：**sin/cos 这套具体公式是 Transformer 论文原创，但它站在"位置编码"这个已有概念的肩膀上，而"旋转/相对位置"的深层含义是后人补全的。**


### 1.6. `div_term` 是什么

```python
# 论文公式：div_term = 1 / 10000^(2i / d_model)
div_term = torch.exp(
  torch.arange(0, d_model, 2).float() * (-math.log(10000.0) / d_model)
)
```

`div_term` = `10000^(-2i/d_model)`，是一个**频率序列**：

- 不同维度 i 对应不同频率
- 低维（i 小）→ 频率高，波长短 → 捕捉**相邻位置**的差异
- 高维（i 大）→ 频率低，波长长 → 捕捉**远距离位置**的差异

相当于用一组不同"粗细"的波浪给每个位置打上独一无二的指纹。


### 1.7. 最后一步 unsqueeze

```python
pe = pe.unsqueeze(0)       # [1, max_len, d_model]
```

`unsqueeze(0)` 在最前面加一维 batch 维度，从 `[max_len, d_model]` 变成 `[1, max_len, d_model]`，这样在 forward 里才能和输入 `x`（形状 `[batch, seq_len, d_model]`）直接相加：

```python
x = x + self.pe[:, : x.size(1)]
```

### 1.8. div_term 推导

#### 1.8.1. 核心恒等式

$$a^b = e^{b \cdot \ln a}$$

这是 exp 和 log 互为逆运算的直接推论。论文的 `div_term` 就靠它变形。

#### 1.8.2. 逐步推导

论文公式：

$$\text{div\_term} = \frac{1}{10000^{2i/d_{model}}}$$

**第 1 步：分母的负次幂**

$$\frac{1}{x^a} = x^{-a}$$

所以：

$$\text{div\_term} = 10000^{-2i/d_{model}}$$

**第 2 步：套用恒等式 `a^b = e^{b·ln a}`**

这里 `a = 10000`，`b = -2i/d_model`：

$$\text{div\_term} = e^{(-2i/d_{model}) \cdot \ln 10000}$$

**第 3 步：把 `2i` 提到外面**

$$\text{div\_term} = e^{2i \cdot (-\ln 10000 / d_{model})}$$

#### 1.8.3. 对照代码

```python
div_term = torch.exp(
  torch.arange(0, d_model, 2).float() * (-math.log(10000.0) / d_model)
)
```

逐项对应：

| 代码      | 数学含义  |
| ------------ | ------------------- |
| `torch.arange(0, d_model, 2)`| `[0, 2, 4, 6, ...]` = **2i 的序列**（i = 0,1,2,…，步长 2 直接生成偶数） |
| `* (-math.log(10000.0) / d_model)` | 乘上 `-ln(10000)/d_model`|
| `torch.exp(...)`      | 对每个元素做 `e^(...)`|

合起来就是：

```
exp( 2i * (-ln(10000)/d_model) )  =  10000^(-2i/d_model)  =  1/10000^(2i/d_model)
```

#### 1.8.4. 为什么 arange 步长是 2

`torch.arange(0, d_model, 2)` 生成 `[0, 2, 4, ..., d_model-2]`，这本身就是 `2i`（i 从 0 到 d_model/2-1），**不用再额外乘 2**。所以代码里没有显式的 `* 2`，它藏在"步长 2"里了。

#### 1.8.5. 为什么要这么绕

直接用幂运算也能写，比如 `1 / (10000 ** (torch.arange(...) / d_model))`。但论文/工程上习惯用 exp+log 形式，原因：

1. **数值更稳定**——避免大数幂运算的溢出/精度问题
2. **计算更快**——`exp` 和 `log` 有硬件加速，幂运算底层也是转成 exp+log 的
3. **和论文公式的向量化写法天然对齐**——整段一次性算完所有维度的 div_term

#### 1.8.6. 再给个具体数字感受一下

假设 `d_model = 4`，`ln(10000) ≈ 9.2103`：

```
2i 序列:        [0, 2]
乘 -9.2103/4:   [0, -4.6052]
exp:            [e^0, e^-4.6052] = [1.0, 0.01]
```

即 div_term = `[1.0, 0.01]`，对应 `i=0` 时频率项 `10000^0 = 1`，`i=1` 时 `10000^(-2/4) = 10000^-0.5 = 0.01`。对上了。

一句话：**`x^b = exp(b·ln x)` 这一个恒等式，把论文的分数幂换成了 exp 里的乘法，代码就是在算这个 `b·ln x`，其中 `b = 2i·(-1/d_model)`，`x = 10000`。**

### 1.9. unsqueeze

`unsqueeze` 是在张量**指定位置插入一个大小为 1 的维度**，用于让形状匹配运算要求。

#### 1.9.1. 基本含义

`unsqueeze(dim)` = 在第 `dim` 维（从 0 开始数）插入一个维度 1。

```
x = torch.tensor([1, 2, 3])        # 形状 [3]
x.unsqueeze(0)                      # 形状 [1, 3]   ← 最前面插一维
x.unsqueeze(1)                      # 形状 [3, 1]   ← 中间插一维
x.unsqueeze(-1)                     # 形状 [3, 1]   ← 最后面插一维
```

#### 1.9.2. 两个实际用法

```python
position = torch.arange(0, max_len).unsqueeze(1).float()   # [max_len, 1]
```

```python
pe = pe.unsqueeze(0)    # [1, max_len, d_model]
```

#### 1.9.3. `unsqueeze(1)` —— 把行向量变列向量（为了广播）

```python
position = torch.arange(0, max_len).unsqueeze(1)
```

- `torch.arange(0, max_len)` → `[max_len]`，一维向量，比如 `[0, 1, 2, 3]`
- `.unsqueeze(1)` → `[max_len, 1]`，变成"列向量"

为什么要这么做？看下一行：

```python
div_term = torch.exp(...)                       # [d_model/2]  行向量
pe[:, 0::2] = torch.sin(position * div_term)
```

`position` 是 `[max_len, 1]`（列），`div_term` 是 `[d_model/2]`（行），两者相乘时广播成 `[max_len, d_model/2]` 的矩阵——**每一行是一个位置，每一列是一个频率维度**。

如果 `position` 还是 `[max_len]`，乘 `[d_model/2]` 就广播不成二维矩阵了。`unsqueeze(1)` 的作用就是**把它摆成"列向量"，好和"行向量"做外积**。

#### 1.9.4. `unsqueeze(0)` —— 加 batch 维度（为了和输入相加）

```python
pe = pe.unsqueeze(0)                            # [1, max_len, d_model]
```

- 原 `pe` 是 `[max_len, d_model]`
- `.unsqueeze(0)` → `[1, max_len, d_model]`，最前面多了个 `1`

为什么要加？看 forward 里怎么用：

```python
x = x + self.pe[:, : x.size(1)]
```

输入 `x` 的形状是 `[batch, seq_len, d_model]`（三维）。而 `pe` 是 `[max_len, d_model]`（二维），维度数都不对，没法直接相加。

`unsqueeze(0)` 把 `pe` 变成 `[1, max_len, d_model]` 后，那个 `1` 就是 batch 维，相加时自动**广播**到每个样本——所有 batch 里的句子共享同一份位置编码（位置编码本来就只跟位置有关，跟具体哪个样本无关）。

#### 1.9.5. 对比记忆

| 写法 | 形状变化 | 典型用途 |
|---|---|---|
| `x.unsqueeze(0)` | `[d]` → `[1, d]` | 加 batch 维，让单个样本能进 batch 模型的 forward |
| `x.unsqueeze(1)` | `[d]` → `[d, 1]` | 变列向量，和行向量广播成矩阵 |
| `x.unsqueeze(-1)` | `[d]` → `[d, 1]` | 同上（-1 就是最后一维，等价于 unsqueeze(1) 当 x 是二维时） |

#### 1.9.6. 和 squeeze 相反

`squeeze(dim)` 是删除大小为 1 的维度，两者互逆：

```python
x.unsqueeze(0).squeeze(0)   # 又变回原样
```

#### 1.9.7. 一句话总结

- **`unsqueeze(1)`**：把 `[max_len]` 变成 `[max_len, 1]`，是为了让位置向量和频率向量广播出二维矩阵。
- **`unsqueeze(0)`**：把 `[max_len, d_model]` 变成 `[1, max_len, d_model]`，是为了补上 batch 维度，让位置编码能和三维的输入 `x` 相加。

核心就是一句话：**在指定位置插一个大小为 1 的维度，好让后续的广播/加法成立。**

## 2. 缩放点积注意力 (Scaled Dot-Product Attention)

论文 3.2.1 节

```python
#    Attention(Q, K, V) = softmax(QK^T / sqrt(d_k)) V
#
# mask 的作用：把「不该被看到的位置」置为 -inf，softmax 后概率归零。
# 两种常见 mask：
#   - padding mask：屏蔽 <pad> 填充位置
#   - causal mask (下三角)：解码时只能看到「当前及之前」的位置（自回归）
def scaled_dot_product_attention(q, k, v, mask=None, dropout=None):
    """
    q: [batch, heads, q_len, d_k]
    k: [batch, heads, k_len, d_k]
    v: [batch, heads, v_len, d_v]
    mask: [batch, heads, q_len, k_len] 或可广播形状，True 表示「被屏蔽」
    """
    d_k = q.size(-1)
    # scores: [batch, heads, q_len, k_len]
    scores = torch.matmul(q, k.transpose(-2, -1)) / math.sqrt(d_k)

    if mask is not None:
        # masked_fill：mask 为 True 的地方填一个极小值(-1e9)，softmax 后变成 0
        scores = scores.masked_fill(mask, -1e9)

    attn = F.softmax(scores, dim=-1)
    if dropout is not None:
        attn = dropout(attn)

    output = torch.matmul(attn, v)   # [batch, heads, q_len, d_v]
    return output, attn
```




### 2.1. `k.transpose(-2, -1)` 是转置最后两维

```
q:  [batch, heads, q_len, d_k]
k:  [batch, heads, k_len, d_k]
kᵀ: [batch, heads, d_k,  k_len]   ← 转置后
```

转置的目的是让 `q` 的最后一维 `d_k` 和 `kᵀ` 的倒数第二维 `d_k` 对齐，才能做矩阵乘法。

### 2.2. `torch.matmul` 是做点积的意思，得到“相似度分数”

```
scores: [batch, heads, q_len, k_len]
```

`scores[i][j]` = 第 i 个 query 和第 j 个 key 的内积 = 它们有多相关。分数越大，说明这个 key 越值得被当前 query "关注"。

### 2.3. $\div \sqrt{d_k}$

这是关键的一步。点积结果的大小会随着维度 `d_k` 增大而增大（因为是把 `d_k` 个数乘起来再相加）。`d_k` 很大时（比如 512），点积值会很大，导致 softmax 进入"饱和区"，梯度趋近 0，训练不动。

除以 `√d_k` 把分数拉回正常范围，让 softmax 保持"有区分度"而不是退化成 one-hot。论文里的原话：

> We suspect that for large values of d_k, the dot products grow large in magnitude, pushing the softmax function into regions where it has extremely small gradients. To counteract this effect, we scale the dot products by 1/√d_k.



## 3. 多头注意力 (Multi-Head Attention)

论文 3.2.2 节

```python
# 把 Q/K/V 投影到 h 个不同的子空间，并行做注意力，再拼接。
# 好处：让模型同时关注不同位置、不同表示子空间的信息。
class MultiHeadAttention(nn.Module):
    def __init__(self, d_model: int, num_heads: int, dropout: float = 0.1):
        super().__init__()
        assert d_model % num_heads == 0, "d_model 必须能被 num_heads 整除"
        self.num_heads = num_heads
        self.d_k = d_model // num_heads

        # 论文里 Q/K/V/O 是四组可学习线性变换
        self.w_q = nn.Linear(d_model, d_model)
        self.w_k = nn.Linear(d_model, d_model)
        self.w_v = nn.Linear(d_model, d_model)
        self.w_o = nn.Linear(d_model, d_model)

        self.dropout = nn.Dropout(dropout)

    def forward(self, q, k, v, mask=None):
        batch = q.size(0)

        # 1) 线性投影，然后按 head 切分：
        #    [batch, q_len, d_model] -> [batch, q_len, heads, d_k] -> [batch, heads, q_len, d_k]
        q = self.w_q(q).view(batch, -1, self.num_heads, self.d_k).transpose(1, 2)
        k = self.w_k(k).view(batch, -1, self.num_heads, self.d_k).transpose(1, 2)
        v = self.w_v(v).view(batch, -1, self.num_heads, self.d_k).transpose(1, 2)

        # 2) 缩放点积注意力
        out, _ = scaled_dot_product_attention(q, k, v, mask, self.dropout)

        # 3) 拼接多个 head，再过一次线性变换
        #    [batch, heads, q_len, d_k] -> [batch, q_len, d_model]
        out = out.transpose(1, 2).contiguous().view(batch, -1, self.num_heads * self.d_k)
        return self.w_o(out)
```


### 先看整体意图

多头注意力 = 把词向量"切成"多个头，每个头独立算一遍注意力，最后拼回来。这段代码就是在做"切头"。

### 用具体数字走一遍

假设：

```
batch = 2        （2 个句子）
q_len = 5        （每个句子 5 个词）
d_model = 128    （每个词 128 维向量）
num_heads = 8    （8 个头）
d_k = 128 / 8 = 16   （每个头 16 维）
```

#### 第 1 步：线性投影 `self.w_q(q)`

```python
q = self.w_q(q)
```

`w_q` 是个 `nn.Linear(d_model, d_model)`（line 99），做一次可学习的线性变换。

- 输入：`[2, 5, 128]`
- 输出：`[2, 5, 128]`（形状不变，但值变了）

**为什么要投影？** 让模型学会"怎么把原始词向量映射成 query"。这里的 `w_q`、`w_k`、`w_v` 三套权重就是论文里说的 Q/K/V 三个可学习变换。

#### 第 2 步：切分 `.view(batch, -1, num_heads, d_k)`

```python
q.view(batch, -1, self.num_heads, self.d_k)
# = view(2, 5, 8, 16)
```

把最后的 128 维**切成 8 段，每段 16 维**：

```
原来: [2, 5, 128]          ← 128 维是一整条
切开: [2, 5, 8, 16]        ← 128 = 8 × 16，切成 8 个头，每个头 16 维

[0] [1] [2] [3] [4] [5] [6] [7]    ← 8 个头
每个头是 16 维的小向量
```

`-1` 是"自动推断"，这里它自动算出是 `q_len=5`，不用手写死。

#### 第 3 步：交换维度 `.transpose(1, 2)`

```python
.transpose(1, 2)
# [2, 5, 8, 16]  →  [2, 8, 5, 16]
```

把第 1 维（5）和第 2 维（8）对调：

```
之前: [batch, q_len, heads, d_k]   = [2, 5, 8, 16]
之后: [batch, heads, q_len, d_k]   = [2, 8, 5, 16]
```

**为什么要换？** 把 `heads` 维度提到前面，这样后面做注意力时，8 个头可以**并行独立计算**——每个头都是 `[batch, q_len, d_k]` 的小矩阵，互不干扰。

这正是注释里写的形状变化：

```110:110:transformer_pytorch.py
        #    [batch, q_len, d_model] -> [batch, q_len, heads, d_k] -> [batch, heads, q_len, d_k]
```

### 完整形状变化汇总

| 步骤 | 操作 | 形状 |
|---|---|---|
| 输入 | q 原始 | `[2, 5, 128]` |
| 投影 | `w_q(q)` | `[2, 5, 128]` |
| 切分 | `.view(2, -1, 8, 16)` | `[2, 5, 8, 16]` |
| 换位 | `.transpose(1, 2)` | `[2, 8, 5, 16]` |

`k` 和 `v` 完全一样的操作（line 112-113），只是用各自的 `w_k`、`w_v` 权重。

#### 为什么叫"多头"

一个词向量 128 维，切成 8 个 16 维的小向量，就是 8 个"头"。每个头用不同的 `w_q` 投影出来的部分，所以**每个头关注的侧重点不同**：

- 有的头可能关注"相邻词"的语法关系
- 有的头可能关注"远处词"的指代关系

这比一个"大头"（128 维一次性算）更能捕捉多样化的关系。论文原话：让模型关注"不同表示子空间"的信息。

### 切完之后

切好的 q/k/v 送进注意力函数：

```116:116:transformer_pytorch.py
        out, _ = scaled_dot_product_attention(q, k, v, mask, self.dropout)
```

算完后，8 个头的结果再拼回来（line 120 的 `.view(batch, -1, num_heads * d_k)`），恢复成 128 维。

---

一句话：**这段代码在"分头"——先用 w_q/w_k/w_v 投影，再把 128 维切成 8×16 的 8 个头，最后 transpose 把头的维度提到前面，让 8 个头能并行独立算注意力。**


## 4. 前馈网络 (Position-wise Feed-Forward Network)

论文 3.3 节

```python
#    FFN(x) = max(0, xW1 + b1) W2 + b2
# 每个位置独立作用（position-wise），中间维度 d_ff 通常是 d_model 的 4 倍。
class PositionwiseFeedForward(nn.Module):
    def __init__(self, d_model: int, d_ff: int, dropout: float = 0.1):
        super().__init__()
        self.w_1 = nn.Linear(d_model, d_ff)
        self.w_2 = nn.Linear(d_ff, d_model)
        self.dropout = nn.Dropout(dropout)

    def forward(self, x):
        return self.w_2(self.dropout(F.relu(self.w_1(x))))
```

## 5. 编码器层 (Encoder Layer)

论文 3.1 节

```python
# 每个 Encoder 层 = 多头自注意力 + 前馈网络，各自带残差连接 + LayerNorm。
# 这里用论文原版的「后归一化 (post-norm)」：x + Sublayer(x)，再接 LayerNorm。
class EncoderLayer(nn.Module):
    def __init__(self, d_model, num_heads, d_ff, dropout=0.1):
        super().__init__()
        self.self_attn = MultiHeadAttention(d_model, num_heads, dropout)
        self.ffn = PositionwiseFeedForward(d_model, d_ff, dropout)
        self.norm1 = nn.LayerNorm(d_model)
        self.norm2 = nn.LayerNorm(d_model)
        self.dropout = nn.Dropout(dropout)

    def forward(self, x, mask):
        # 自注意力：Q=K=V=x
        x = self.norm1(x + self.dropout(self.self_attn(x, x, x, mask)))
        x = self.norm2(x + self.dropout(self.ffn(x)))
        return x
```

里面 `x + ...` 是**残差连接**，`self.norm1(...)` 是 **LayerNorm**。分开讲。

### 残差连接（Residual Connection）

#### 核心公式

$$输出 = x + F(x)$$

`x` 是输入，`F(x)` 是子层（比如注意力层）算出来的东西，两者**相加**。

#### 直觉：留一条"抄近路"的通道

想象一个工厂流水线，产品 `x` 要经过一道复杂工序（注意力层）变成 `F(x)`。

- 没有残差：产品完全被工序"改造"，原始信息可能丢失
- 有残差：`x + F(x)`，**原始产品 x 直接抄近路到终点**，工序只负责"额外加工一部分"

这样即使 `F(x)` 这道工序学得不好（甚至输出全是垃圾），`x` 还在，信息不会丢。

#### 为什么这么重要（解决梯度消失）

深层网络（Transformer 堆几十层）训练时，梯度要**从最后一层反向传回第一层**，每过一层乘一次，越传越小，最后第一层几乎收不到梯度 → 训不动。

残差连接的 `x + F(x)` 让梯度有了一条"直达高速路"——梯度可以直接流回 `x`，不用层层衰减。**这是深层网络能训练的关键**，来自 ResNet（2015）。

#### 一句话

**残差 = 输入 + 子层输出，给信息留一条短路，保证梯度能传回去、信息不丢失。**

### 二、LayerNorm（层归一化）

#### 核心公式

对每个词向量 `x`（长度 d_model），先算它的均值和方差，再标准化：

$$\hat{x} = \frac{x - \mu}{\sqrt{\sigma^2 + \epsilon}}$$

其中 `μ` 是 x 的平均值，`σ²` 是方差，`ε` 是防除零的小数。然后再乘一个可学习参数 γ 加 β：

$$y = \gamma \hat{x} + \beta$$

#### 直觉：把数据"拉回标准范围"

神经网络一层层算下来，数值可能越来越大（爆炸）或越来越小（消失）。LayerNorm 就是**每个词向量内部做一次"归位"**：让它的均值变成 0、方差变成 1。

比如一个词向量 `[100, 200, 50, 300]`，数值很大，归一化后变成 `[-1.2, 0.4, -1.5, 0.9]` 这种"居中、缩放合理"的值，下一层算起来就稳定多了。

#### 关键：它和 BatchNorm 的区别（为什么 Transformer 用 LayerNorm）

| | BatchNorm | LayerNorm |
|---|---|---|
| 归一化维度 | 对**同一个特征**、跨**一批样本**算均值方差 | 对**单个样本的整条向量**算均值方差 |
| 依赖 batch | 依赖，batch 太小就不准 | **不依赖 batch** |
| 适合 | CNN（图像） | RNN / Transformer（序列） |

Transformer 用 LayerNorm 的原因：

1. **不依赖 batch 大小**——翻译时句子长度不一，batch 大小也常变，BatchNorm 会不稳定
2. **每个位置独立归一化**——每个词的向量单独归一化，不影响其他词
3. **适配变长序列**——天然适合"一句话里每个 token"这种结构

#### 一个具体例子

假设某个词向量（d_model=4）：

```
x = [2, 4, 4, 6]

μ  = (2+4+4+6)/4 = 4
σ² = ((2-4)²+(4-4)²+(4-4)²+(6-4)²)/4 = (4+0+0+4)/4 = 2

x̂ = (x - 4) / √2 = [-1.414, 0, 0, 1.414]
```

现在均值是 0，方差是 1 了。再乘 γ 加 β 让模型自己调整。

### 两者怎么配合

```python
x = self.norm1(x + self.dropout(self.self_attn(x, x, x, mask)))
```

执行顺序：

1. `self.self_attn(...)` → 算注意力输出 `F(x)`
2. `x + ...` → **残差连接**，原始 x 加回来
3. `self.norm1(...)` → **LayerNorm**，把相加后的结果归一化

这个结构叫 **"残差 + 归一化"（post-norm，论文原版写法）**，Transformer 每一层都是"子层 → 加残差 → LayerNorm"，重复堆叠。

### 一句话总结

- **残差连接**：`x + F(x)`，给信息留短路，解决梯度消失，让深层网络能训练。
- **LayerNorm**：把每个词向量归一化（均值 0 方差 1），稳定数值、加速收敛，且不依赖 batch 大小，适合变长序列。

两者配合 = Transformer 每个子层的标准骨架：**先算子层 → 加残差 → 归一化**。

## 6. 解码器层 (Decoder Layer)

论文 3.1 节

```python
# 每个 Decoder 层比 Encoder 多一个「交叉注意力」：
#   - masked self-attention：只能看已生成的位置（causal mask）
#   - cross-attention：Q 来自 decoder，K/V 来自 encoder 输出
class DecoderLayer(nn.Module):
    def __init__(self, d_model, num_heads, d_ff, dropout=0.1):
        super().__init__()
        self.self_attn = MultiHeadAttention(d_model, num_heads, dropout)
        self.cross_attn = MultiHeadAttention(d_model, num_heads, dropout)
        self.ffn = PositionwiseFeedForward(d_model, d_ff, dropout)
        self.norm1 = nn.LayerNorm(d_model)
        self.norm2 = nn.LayerNorm(d_model)
        self.norm3 = nn.LayerNorm(d_model)
        self.dropout = nn.Dropout(dropout)

    def forward(self, x, enc_out, src_mask, tgt_mask):
        # 1) 掩码自注意力（目标序列内部，带 causal mask）
        x = self.norm1(x + self.dropout(self.self_attn(x, x, x, tgt_mask)))
        # 2) 交叉注意力（query=decoder，key/value=encoder 输出）
        x = self.norm2(x + self.dropout(self.cross_attn(x, enc_out, enc_out, src_mask)))
        # 3) 前馈
        x = self.norm3(x + self.dropout(self.ffn(x)))
        return x
```

## 7. 完整 Transformer (Encoder + Decoder)

```python
class Transformer(nn.Module):
    def __init__(self, src_vocab, tgt_vocab, d_model=512, num_heads=8,
                 num_layers=6, d_ff=2048, dropout=0.1, max_len=5000):
        super().__init__()
        # 词嵌入 + 位置编码
        self.encoder_embed = nn.Embedding(src_vocab, d_model)
        self.decoder_embed = nn.Embedding(tgt_vocab, d_model)
        self.pos_enc = PositionalEncoding(d_model, max_len, dropout)

        # N 层堆叠
        self.encoder = nn.ModuleList([
            EncoderLayer(d_model, num_heads, d_ff, dropout) for _ in range(num_layers)
        ])
        self.decoder = nn.ModuleList([
            DecoderLayer(d_model, num_heads, d_ff, dropout) for _ in range(num_layers)
        ])

        # 输出投影：d_model -> 词表大小，softmax 后得到每个词的预测概率
        self.generator = nn.Linear(d_model, tgt_vocab)

        self.d_model = d_model
        self._init_weights()

    def _init_weights(self):
        # 论文提到用 xavier 初始化，embedding 乘以 sqrt(d_model)
        for p in self.parameters():
            if p.dim() > 1:
                nn.init.xavier_uniform_(p)

    def forward(self, src, tgt, src_mask, tgt_mask):
        # src: [batch, src_len], tgt: [batch, tgt_len]
        enc_out = self.encode(src, src_mask)
        return self.decode(enc_out, tgt, src_mask, tgt_mask)

    def encode(self, src, src_mask):
        x = self.encoder_embed(src) * math.sqrt(self.d_model)
        x = self.pos_enc(x)
        for layer in self.encoder:
            x = layer(x, src_mask)
        return x

    def decode(self, enc_out, tgt, src_mask, tgt_mask):
        x = self.decoder_embed(tgt) * math.sqrt(self.d_model)
        x = self.pos_enc(x)
        for layer in self.decoder:
            x = layer(x, enc_out, src_mask, tgt_mask)
        return self.generator(x)   # [batch, tgt_len, tgt_vocab]
```

## 8. mask 构造工具

```python
def make_pad_mask(seq, pad_idx):
    """padding mask：位置为 <pad> 的置 True（屏蔽）。
    形状 [batch, 1, 1, seq_len]，可广播到注意力分数的最后两维。"""
    return (seq == pad_idx).unsqueeze(1).unsqueeze(2)

def make_causal_mask(seq_len):
    """causal mask：下三角，屏蔽「未来」位置。
    形状 [1, 1, seq_len, seq_len]。"""
    mask = torch.triu(torch.ones(seq_len, seq_len), diagonal=1).bool()
    return mask.unsqueeze(0).unsqueeze(0)
```

## 9. 一个能直接跑的小型演示任务：序列反转 (reverse)

```python
def train_demo():
    torch.manual_seed(0)

    # 小规模超参（只为快速跑通，真实任务可调大）
    vocab_size, d_model, num_heads = 32, 64, 4
    num_layers, d_ff, seq_len = 2, 128, 10
    batch_size, steps = 64, 2500
    warmup_steps = 400      # Noam 学习率 warmup 步数

    model = Transformer(vocab_size, vocab_size, d_model, num_heads,
                        num_layers, d_ff, dropout=0.1, max_len=64)
    # 论文用 Adam(betas=(0.9, 0.98), eps=1e-9)；初始 lr 由 Noam 公式在每一步覆盖
    optimizer = torch.optim.Adam(model.parameters(), lr=0, betas=(0.9, 0.98), eps=1e-9)
    loss_fn = nn.CrossEntropyLoss(ignore_index=0)   # 忽略 pad

    model.train()
    for step in range(1, steps + 1):
        src, tgt = make_reverse_batch(batch_size, seq_len, vocab_size)

        # decoder 的输入是 tgt 去掉最后一个词（shift right），预测目标是 tgt 去掉第一个词
        tgt_input = tgt[:, :-1]       # [batch, seq_len-1]
        tgt_label = tgt[:, 1:]        # [batch, seq_len-1]

        src_mask = make_pad_mask(src, pad_idx=0)
        tgt_mask = make_causal_mask(tgt_input.size(1)) | make_pad_mask(tgt_input, pad_idx=0)

        logits = model(src, tgt_input, src_mask, tgt_mask)   # [batch, seq_len-1, vocab]
        loss = loss_fn(logits.reshape(-1, vocab_size), tgt_label.reshape(-1))

        optimizer.zero_grad()
        loss.backward()
        # Noam warmup 学习率：lr = d_model^(-0.5) * min(step^(-0.5), step * warmup^(-1.5))
        # 学习率先升后降，避免一开始 lr 太大导致训练震荡/发散
        lr = d_model ** (-0.5) * min(step ** (-0.5), step * warmup_steps ** (-1.5))
        for g in optimizer.param_groups:
            g['lr'] = lr
        optimizer.step()

        if step % 100 == 0:
            print(f"step {step:4d}  loss = {loss.item():.4f}  lr = {lr:.6f}")

    # 简单推理演示：看模型能否学会反转
    model.eval()
    with torch.no_grad():
        src, tgt = make_reverse_batch(1, seq_len, vocab_size)
        # 贪心解码：从 <bos>=1 开始，逐词生成，直到遇到 <eos>=2
        generated = [1]
        enc_out = model.encode(src, make_pad_mask(src, pad_idx=0))
        for _ in range(seq_len + 2):   # 最长 = seq_len 个词 + <bos> + <eos>
            tgt_input = torch.tensor([generated]).long()
            tgt_mask = make_causal_mask(tgt_input.size(1))
            logits = model.decode(enc_out, tgt_input, make_pad_mask(src, pad_idx=0), tgt_mask)
            next_token = logits[0, -1].argmax().item()
            generated.append(next_token)
            if next_token == 2:   # <eos>
                break

    print("\n输入 :", src[0].tolist())
    print("目标 :", tgt[0].tolist())
    print("预测 :", generated)
    print("\n如果 loss 降到接近 0，说明模型结构正确、训练流程跑通。")
```
